Single-owner software architecture

EXP-08Registered 8 October 2026

Does giving the serial port and camera a single owning process remove the contention faults seen in V1?

Why this matters

V1 ended with two software stacks that cannot run together. Consolidating them is a prerequisite for running all features at once for long periods.

Evidence so far

  • A Restart=always dashboard service fought the ROS2 camera node for /dev/video0 and corrupted the capture (25 Sep 2026).
  • The ROS2 serial bridge and the web dashboard cannot run together on /dev/ttyACM0.
  • Camera-to-tracker latency fell from 710 ms to ~101 ms median once image topics used depth-1 best-effort QoS (20 Sep 2026).

Planned method

  • Route all hardware access through one owner (ROS2 topics or one service).
  • 24-hour soak test with dashboard, tracking and fall detection running together.

Measures

  • End-to-end latency
  • Device conflicts
  • Crashes / restarts per day
