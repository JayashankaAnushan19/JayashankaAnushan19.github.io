Experiment · Methodology

A reusable fault-diagnosis protocol for low-cost robots

EXP-09Registered 8 October 2026

Can the systematic-elimination method used throughout V1 be formalised into a protocol that measurably shortens time-to-root-cause?

Why this matters

Much of V1’s value was in how faults were found, not just fixed. Written down and measured, that method is a contribution in its own right.

Evidence so far

  • V1 root-caused a defective RFID reader, a damaged I²C SCL pin (moved to a software I²C bus), RFID power sensitivity, unresponsive Serial1 pins and a PIR stuck HIGH — each by isolation testing.
  • A web-based diagnostics tool (flash a test sketch and watch live serial, port 5050) was built for exactly this work (6 Sep 2026).

Planned method

  • Write the protocol down; apply it to every new fault in V2.
  • Record hypotheses tested and time to root cause for each fault.

Measures

  • Time to root cause
  • Hypotheses tested per fault
  • Faults resolved vs. documented as limitations
