V2.0 opens: inheriting the platform and auditing the record

DN-20261008Jayashanka Anushan

CARA V2.0 starts today as my own independent continuation of the V1 robot. The code moved to a new repository with a fresh history; the V1 history stays in the original repository. This notebook, the experiment register and the journal open with it.

What was done

  • Read through everything inherited: both V1 daily logs, the canonical firmware (cara_main_mega_gsm.ino), the web dashboard (remote_control.py), the ROS2 launch setup, test records and the classifier reports.
  • Made the repository safe for its first push: the ~600 MB presentation deck and ~2 GB of raw test video are kept local (GitHub rejects files over 100 MB); dashboard runtime files — which hold the admin password in plain text and client IP logs — are excluded; Git LFS configuration cleaned and extended to Office, CAD and model files.
  • Backfilled the engineering log for 30 Sep – 7 Oct from dated code comments and the dashboard’s own logs (no git history exists for those days), and archived the second, Jetson-side V1 log.
  • Opened this documentation site and research journal: documentation pages, Daily Notes, Journal entries and an Experiment Register of nine research threads.

Findings from the audit

Finding 1 — two classifiers, one reportedThe V1 figures of 87.6 % test / 89.6 % cross-validated fall-detection accuracy belong to the 644-sample model that the code actually loads. A second, older file (fall_classifier.pkl, 461 samples) reports 95.7 % test accuracy and is still used by two test scripts. The smaller dataset’s higher score should not be quoted for the deployed system.
Finding 2 — the final demo path did not use the classifierFrom 3 October fall detection ran inside the dashboard process, which logged “No trained ML classifier found” and used the rule-based fallback. The classifier figures describe the offline / ROS2 path, not the final demonstration configuration.
Finding 3 — the repository may not match the robotDashboard comments dated 6 October describe a firmware software-clock fallback and an encoder stall guard that are absent from the repository firmware, and the firmware header’s LED/servo pins contradict the 29 September wiring log. Opened as EXP-01; no firmware changes until the robot and repository agree.

Decisions

  • Negative and inconvenient results are recorded as findings, not removed.
  • Raw videos stay local; public copies go to YouTube and are embedded here.
  • Formal write-ups go to the Journal only when there is a real result; this notebook carries the day-to-day.
