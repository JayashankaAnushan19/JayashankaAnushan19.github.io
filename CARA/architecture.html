Software Design

System Architecture

CARA's software is split between two controllers: the Jetson Nano handles AI and ROS, while the Arduino Mega manages all real-time peripherals through a 5-state machine.

Dual-Controller Design

The architecture separates intelligence from execution. The NVIDIA Jetson Nano runs ROS Noetic on Ubuntu 18.04, handling all computationally intensive tasks — computer vision, camera streaming, person tracking, and web interfaces. It communicates decisions to the Arduino Mega 2560 via UART serial at 9600 baud. The Arduino executes those decisions through its 5-state machine, directly controlling motors, sensors, GSM, RFID, LCD, buzzers, and LEDs.

This split was a deliberate design decision: the Arduino's real-time loop runs non-blocking polling cycles at ~50ms, which would be impossible to guarantee in ROS's executor model. Conversely, MediaPipe Pose Estimation and Flask streaming require the GPU and Linux stack available only on Jetson.

ROS Nodes (Jetson Nano)

NodeTriggerFunctionOutputs
fall_detection Camera frame MediaPipe Pose at 12–15 fps. Checks: LEFT_HIP y >0.77, RIGHT_HIP y >0.77, LEFT_SHOULDER y >0.55. All three must persist for 2 seconds before fall is confirmed. Publishes /fall_detected · Outputs nose_x for pan_tilt
serial_bridge ROS topics Aggregates commands from all nodes into a single UART serial stream to Arduino. Implements command priority: FALL_DETECTED overrides all movement commands. USB Serial commands to Arduino
camera_stream HTTP request Flask MJPEG server on port 5000. Endpoint /video_feed. Runs in daemon thread. Streams /dev/video0 at 720p. Accessible from any phone browser on local network. HTTP MJPEG stream
person_lock Camera frame Layer 1: RFID UID registered at session start. Layer 2: OpenCV HSV filter tracks orange wristband (user wears it). Publishes TARGET_LOST if band absent for 10s. /target_visible topic
pan_tilt nose_x + PIR Calculates chassis rotation direction vs 320px frame centre (left/right aiming is done by rotating the chassis, not a pan servo — only tilt is a physical servo). If nose_x < 140 → PAN_LEFT; if nose_x > 180 → PAN_RIGHT. PIR direction overrides if no visual target. PAN_LEFT/RIGHT via serial
remote_control HTTP POST Receives movement commands from phone web interface. Forwards MOVE_FORWARD / STEER_LEFT / STEER_RIGHT / STOP to Arduino. Obstacle avoidance always overrides. Movement commands via serial
health_management DS3231 time match Polls RTC time via serial. Medication reminders at 08:00, 13:00, 18:00, 22:00. 15-min RFID confirm window. Missed → sendSMS(). Daily check-in at 12:00. Heatstroke at 38°C. Medication trigger · SMS alerts

5-State Machine (Arduino)

The Arduino executes a single non-blocking loop that services all peripherals at ~50ms intervals. The system state governs which actions are taken each cycle.

StateBehaviour
💤 Idle No target detected. Motors stopped. Ultrasonic sensors polling every 50ms. PIR sensors monitoring. LCD shows standby message. Green LED.
🚶 Active PIR triggered, RFID confirmed. Robot moves toward target. Person_lock tracking begins. Obstacle avoidance enforced. Amber LED pulsing.
👁️ Monitoring Target in frame, MediaPipe fall detection active. Robot stationary or slow-follow. Fall detection threshold check running every frame. Blue LED.
🚨 Alert Fall confirmed. Motors stopped. GSM module (SIM76xx) sends SMS. LCD shows "FALL DETECTED — HELP CALLED". Buzzer beeps. Red LED solid. 30s cooldown enforced.
🔄 Reset Alert cooldown complete. System checks for continued fall posture. If cleared, returns to IDLE. If posture persists, holds ALERT. Amber LED rapid pulse.

Safety Invariant

Obstacle avoidance (20 cm threshold) overrides are enforced in every state, including ALERT and remote_control. No command — from any source — can cause the robot to move into an obstacle. (Cliff detection is designed into the safety architecture but postponed to v1.1 — see Docs.)

Communication Protocols

UART Serial (Jetson ↔ Arduino)

9600 baud via USB Serial port. One-way command protocol: Jetson decides, Arduino executes. Arduino reads with Serial.readStringUntil('\n'). Commands are plain ASCII strings terminated with newline.

Command set: FALL_DETECTED · STEER_LEFT · STEER_RIGHT · MOVE_FORWARD · SLOW_DOWN · STOP · TARGET_LOST · PAN_LEFT · PAN_RIGHT

I2C Bus (LCD + RTC)

Shared two-wire bus (SDA on Arduino A4, SCL on A5). LCD at address 0x27, DS3231 RTC at 0x68. Both share the same two wires, reducing GPIO usage. Scalable — additional I2C devices can join the bus without new pins.

SPI (RFID)

MFRC522 communicates via hardware SPI (MISO/MOSI/SCK on Arduino pins 50/51/52). Slave Select on pin 10. Polling loop in MONITORING and ACTIVE states checks for UID match every 500ms.

GSM AT Commands (SIM76xx)

SoftwareSerial on Arduino pins 2 & 3. SMS sequence: AT+CMGF=1 (text mode) → AT+CMGS="+[number]" → message body → 0x1A (Ctrl+Z, send). 4.0V regulated supply, 1000µF cap. Same AT command set works on SIM800L, used in a Sri Lanka deployment where 2G is still active.
